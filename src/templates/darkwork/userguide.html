Darkworks Lab — User Guide

Package: com.darkworks.lab
Version: 1.0.0+1
Platforms: Android and Linux

Darkworks Lab is a local-first application for learning, experimentation, and authorized defensive research. It inspects local devices, network activity, hardware telemetry, storage, and system health. It is not professional security advice and does not guarantee detection or protection. Use it only on systems and data you are authorized to inspect, and independently verify every result before taking action.

Getting started

On the first Android launch the app requests location and Bluetooth-related permissions. Grant the permissions needed for the features you use. Use Initialize perimeter in the dashboard header, or pull down on the dashboard, to run the security service scan. Linux does not show the Android permission dialogs.

Dashboard

  • Status header: shield artwork, active status, and the perimeter scan control.
  • Quick statistics: Bluetooth and Network / Wi-Fi counts that open filtered device lists.
  • Network discovery: up to four discovered network/Wi-Fi devices with an address summary.
  • Bottom navigation: Status, Sensors, Security, System, and More.
  • Theme toggle: the app-bar sun/moon button switches light and dark mode.

Device discovery

Tap either dashboard statistic to open Device Discovery. The list supports device-type filters, refresh, and the device details/actions currently implemented. Results are local observations and may be limited by permissions, adapter state, and network reachability.

Screens

  • Sensors: accelerometer, gyroscope, magnetometer, ambient light, battery, and location data when available.
  • Security: network scanning, port/service assessment, security reports, and event logs.
  • System: device information, CPU/memory/battery metrics, network identity, active sockets, and aggregates.
  • File integrity scan: walks accessible local files, reports progress, and classifies findings by risk.
  • Radio spectrum monitor: SDR hardware availability and spectrum/status information (supported SDR required).
  • System event logs: local events with severity styling and date filtering.
  • Settings: settings and appearance controls exposed by the current build.

Always review a file integrity result before deleting a file, and do not treat a clean result as proof that a device is secure.

Privacy and safety

Monitoring data is handled on the local device. This is educational software provided without a guarantee of complete detection or protection.

Troubleshooting

  • No Bluetooth results: enable Bluetooth, grant scan/connect permissions, and refresh.
  • No network results: confirm the device is on the intended network and local discovery is permitted.
  • Sensors unavailable: check OS permissions, hardware support, and stream state.
  • Filesystem results incomplete: only paths exposed to the app can be inspected.
  • No radio data: connect a supported SDR with the required host/runtime support.
